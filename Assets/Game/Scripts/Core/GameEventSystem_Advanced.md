# 🕵️‍♂️ CORE ARCHITECTURE: UNDER THE HOOD (ADVANCED)

Здесь описаны низкоуровневые возможности системы сигналов, которые **не рекомендуются** для обычного использования, но полезны для понимания работы "под капотом" или решения специфических задач.

---

## 1. Ручная привязка через `Bind()`

Если вам недостаточно атрибутов (например, нужно динамически подписываться на разные события в рантайме), вы можете использовать `Bind`.

```csharp
protected override void OnEnable()
{
    base.OnEnable(); // КРИТИЧЕСКИ ВАЖНО вызвать базу для работы системы!
    Bind(someEvent, SomeMethod);
}
```

*   **Риск**: Если забыть `base.OnEnable()`, то все атрибуты `[Listen]` и `[OnChanged]` в этом классе **перестанут работать**, так как их инициализация спрятана в родителе.

---

## 2. Прямая реализация `ISignalListener`

Вы можете не наследоваться от `SignalBinder`, а просто реализовать интерфейс.

```csharp
public class RawListener : MonoBehaviour, ISignalListener
{
    public void OnSignalReceived(GameEvent incomingEvent)
    {
        // Ручная фильтрация событий через if или switch
        if (incomingEvent == myEvent) { ... }
    }
}
```

*   **Минус**: Придется самому следить за `RegisterSignal` и `UnregisterSignal` в `OnEnable/OnDisable`, иначе возникнут утечки памяти (Memory Leaks) и ошибки в редакторе.

---

## 3. Наследование от `ScriptableVariableBase`

Если вы создаете систему, которая должна работать с любым типом переменной (не зная, `int` там или `float`), используйте `ScriptableVariableBase`. Он дает доступ к `onValueChanged` и методу `Raise()`.

---

## 4. Рефлексия в SignalBinder

Система атрибутов работает через кэшированную рефлексию. 
1. При первом включении объекта типа `X`, `SignalBinder` сканирует все его поля и методы.
2. Результаты (какие поля слушать и какие методы звать) сохраняются в `static Dictionary`.
3. Все последующие объекты типа `X` используют готовый кэш, не нагружая процессор поиском атрибутов.
